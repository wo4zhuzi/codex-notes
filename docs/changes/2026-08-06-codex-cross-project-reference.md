# 补充 Codex 跨项目参考说明

## 任务背景

项目 B 进行新功能开发时，可能需要参考项目 A 的已有代码或设计。需要沉淀 Codex CLI 的启动方式，并明确主工作目录、额外目录和只读参考之间的权限边界。

## 根因定位

仓库原有 `codex-cli.md` 只记录安装、初始化和基础配置，没有说明如何让 Codex 在项目 B 中工作时访问项目 A。更重要的是，`--add-dir` 容易被误解为只读引用参数，但当前 CLI 将其定义为主工作区之外的额外可写目录，仅靠提示词无法形成系统级只读隔离。

首次补充的命令还隐式依赖默认沙箱模式。实际运行反馈表明，当前环境需要显式设置 `-s workspace-write` 才能正常使用。根因是两个参数职责不同：`workspace-write` 启用工作区写入模式，`--add-dir` 只负责扩展额外可写目录；默认处于 `read-only` 等其他模式时，单独设置 `--add-dir` 无法提供预期写入能力。

## 执行计划

1. 检查工作区状态，避免覆盖用户未提交改动。
2. 搜索现有 Codex CLI 文档，确定最小修改位置。
3. 核对 `-C` 和 `--add-dir` 的当前参数语义。
4. 补充推荐命令、只读约束、安全边界和使用注意事项。
5. 检查 Markdown、链接、敏感信息和 Git diff。

## 变更内容

- 在 `codex-cli.md` 新增“跨项目参考代码”章节。
- 增加以项目 B 为工作根目录、以项目 A 为额外参考目录，并显式启用 `workspace-write` 的完整启动命令。
- 说明 `-s workspace-write` 与 `--add-dir` 的职责和组合关系，避免依赖不同机器上的默认沙箱配置。
- 明确 `--add-dir` 会授予写权限，提示词中的“禁止修改”不是系统级权限隔离。
- 补充只读挂载或只读快照的强隔离建议。
- 补充多个参考目录、空格路径、`AGENTS.md` 和 Git 状态检查等使用边界。
- 标注官方资料链接、核对日期和本机 CLI 版本。

## 验证结果

- 本机 `codex --help` 确认 `-s workspace-write` 是沙箱策略选项，`--add-dir` 定义为主工作区之外的额外可写目录。
- `git diff --check`：通过，无空白错误。
- `codex-cli.md` 的 Markdown 代码围栏数量为偶数，未发现未闭合围栏。
- `README.md` 已有 `codex-cli.md` 快速入口，链接目标存在，无需调整索引。
- 仓库级 `rg -n "TODO|FIXME|your-api-key|sk-" .` 仅命中既有检查命令、示例分支名和 `risk-reviewer` 文本，未发现真实密钥或遗留调试标记。
- 对本次两份文档执行精确占位符和密钥形态扫描，无命中。
- 已人工检查 Markdown diff，命令、参数说明和权限边界与核对结果一致。
- 本机未安装 `markdownlint`，因此未执行该项可选检查。

## 后续建议

- Codex CLI 升级后，如 `codex --help` 中 `--add-dir` 的定义发生变化，应同步更新权限说明和核对日期。
