# Code Review 评估标准

## 适用边界

适用于提交前审查、PR 审查、diff 风险检查、重构评估和测试覆盖检查。

Code Review 的核心要求是基于真实 diff 找缺陷、风险、回归点和测试缺口，而不是复述改动或泛泛评价风格。

## 阶段性评估

检查重点：

- 是否已经读取真实 diff。
- 是否理解需求背景和影响范围。
- 是否优先关注行为风险、兼容性、安全边界和测试缺口。
- 是否需要补充上下文，例如 issue、设计文档、测试结果或调用方。

## 交付评估

检查重点：

- findings 是否有文件和行号。
- findings 是否按严重程度排序。
- 是否区分缺陷、风险、测试缺口和开放问题。
- 没有发现问题时，是否说明残余风险或未覆盖范围。
- 是否避免把风格偏好当作阻塞问题。

## 停止线

出现以下情况应停止并补充上下文：

- 没有读取真实 diff。
- 只复述改动，没有风险判断。
- 结论没有文件、行号或证据。
- 审查范围涉及权限、安全、数据或生产发布，但缺少需求背景。

## 输出要求

最终输出应包含：

- Findings 优先，按严重程度排序。
- 每个 finding 包含文件、行号、问题和影响。
- 开放问题或假设。
- 测试缺口和残余风险。
- 如无问题，明确说明未发现阻塞问题和未覆盖范围。
