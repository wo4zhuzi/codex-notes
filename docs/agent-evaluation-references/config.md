# 配置任务评估标准

## 适用边界

适用于 TOML、YAML、JSON、env 示例、模型配置、CLI 配置、CI 配置、MCP 配置和运行参数调整。

配置任务的核心要求是：格式合法、默认值清楚、兼容影响明确、无敏感信息。

## 阶段性评估

检查重点：

- 配置项含义是否确认。
- 默认值变化是否明确。
- 是否影响生产、权限、发布、成本或模型选择。
- 是否需要保留旧配置兼容。
- 是否能通过 dry-run、解析命令或项目启动验证。

## 交付评估

检查重点：

- TOML、YAML、JSON 或对应格式是否合法。
- 配置能否被加载、dry-run 或示例命令验证。
- 是否包含真实 token、私有代理地址、内部服务 URL 或账号信息。
- 默认值变化和兼容影响是否说明。
- 如修改配置模板，是否保留原有缩进和结构风格。

## 停止线

出现以下情况应停止并交给人确认：

- 涉及生产配置、权限配置、发布配置或 CI/CD 权限。
- 默认值变化会影响成本、权限、安全或线上行为，但没有确认。
- 出现真实 token、私有地址或内部服务 URL。
- 无法验证配置是否能被加载。

## 输出要求

最终输出应包含：

- 修改的配置项和默认值变化。
- 配置格式或加载验证结果。
- 敏感信息扫描结果。
- 兼容影响和未验证项。
- 是否需要人类确认。
- 交付状态。
