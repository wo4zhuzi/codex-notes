# 高风险任务评估标准

## 适用边界

适用于生产、权限、安全、数据迁移、支付、发布流程、CI/CD 权限、真实用户数据和不可逆操作。

高风险标准通常不是独立使用，而是叠加到其他场景。例如生产配置变更应同时参考配置任务标准和本文件。

## 阶段性评估

检查重点：

- 是否已经进入 Spec 或等价的明确方案流程。
- 影响范围、失败后果和回滚路径是否清楚。
- 是否涉及真实数据、生产权限、支付、用户隐私或安全边界。
- 当前步骤是否只读、dry-run 或可回退。
- 是否需要用户确认才能继续。

## 交付评估

检查重点：

- 测试、dry-run、迁移检查或发布前检查是否执行。
- 回滚方案是否明确。
- 权限、审计、日志和监控影响是否说明。
- 是否存在人工审批或二次确认。
- 是否明确哪些操作未执行，例如真实发布、真实迁移或 push。

## 停止线

出现以下情况必须停止并交给人：

- 需求不清。
- 权限边界不清。
- 生产影响不清。
- 回滚方案缺失。
- 涉及真实数据但无确认。
- 需要执行发布、迁移、支付、删除、push 或权限变更。
- 继续操作可能造成不可逆影响。

## 输出要求

最终输出应包含：

- 高风险类型。
- 影响范围。
- 已执行的只读检查、测试或 dry-run。
- 未执行的生产操作。
- 回滚或恢复方案。
- 需要人类确认的问题。
- 交付状态，通常应标明是否仅完成准备工作。
