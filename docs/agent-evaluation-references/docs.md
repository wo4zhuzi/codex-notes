# 文档任务评估标准

## 适用边界

适用于 README、Markdown 笔记、AGENTS.md、配置说明、变更记录、安装步骤和使用手册等文档类任务。

不适用于需要验证业务行为、接口兼容或生产发布的代码任务。

## 阶段性评估

用于文档起草或结构调整过程中，判断方向是否可以继续。

检查重点：

- 内容方向是否符合用户目标。
- 章节结构是否贴合现有文档风格。
- 新增概念是否和已有工作流冲突。
- 是否需要补链接、命令示例或变更记录。

阶段性通过只表示可以继续完善，不代表文档已经可交付。

## 交付评估

建议验证：

```bash
git status --short
rg -n "TODO|FIXME|your-api-key|sk-" .
test -f <新增文档>
rg -n "<新增文档名|关键标题>" README.md *.md
```

检查重点：

- 新增链接是否指向真实文件。
- 示例命令是否和上下文一致。
- 是否没有真实 API Key、Token、私有代理地址或内部服务 URL。
- 如产生仓库文件改动，是否生成或更新 `docs/changes/YYYY-MM-DD-<topic>.md`。
- 未运行的可选检查是否说明，例如 markdownlint。

## 停止线

出现以下情况应停止并交给人确认：

- 发现真实密钥、Token、私有地址或内部服务 URL。
- README 或正文链接指向不存在的文件。
- 新文档与 `AGENTS.md`、工作流或安全规则冲突。
- 第三方工具版本、安装命令或模型名称无法确认且会误导使用者。

## 输出要求

最终输出应包含：

- 评估阶段：阶段性评估或交付评估。
- 文档范围：新增或修改了哪些文档。
- 验证命令和结果。
- 未验证项和剩余风险。
- 交付状态：可交付、部分完成或停止交给人。
