# 重构评估标准

## 适用边界

适用于结构调整、模块拆分、命名整理、去重复、依赖方向调整和内部实现替换。

重构的核心要求是：外部行为不变。结构改善不能替代行为验证。

## 阶段性评估

用于影响范围分析或分步重构过程中。

检查重点：

- 调用方和依赖方向是否查清。
- public API、配置键、数据结构和持久化格式是否保持不变。
- 是否避免无关格式化、重排和大面积移动。
- 当前步骤是否足够小，失败时是否容易回退。
- 局部测试是否支持继续推进。

## 交付评估

检查重点：

- 相关测试是否通过。
- public API、配置键、数据结构是否未意外变化。
- diff 是否主要体现结构调整，而不是混入行为变化。
- 是否说明无法自动验证的行为风险。
- 是否有必要更新文档或变更记录。

## 停止线

出现以下情况应停止并交给人确认：

- public API、数据结构、配置默认值或持久化格式发生非预期变化。
- 无测试保护的大范围重构。
- diff 出现大量无关格式化或目录重排。
- 影响跨模块边界、权限、安全或数据一致性，但没有 Spec。

## 输出要求

最终输出应包含：

- 重构目标。
- 行为不变的证据。
- 影响范围和调用方检查。
- 验证命令和结果。
- 未验证风险。
- 交付状态。
