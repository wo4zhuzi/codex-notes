# 工具集成评估标准

## 适用边界

适用于 RAG、MCP、Function Calling、外部 CLI、代码索引、数据库只读查询、文档检索和第三方工具接入。

工具集成评估的核心不是“模型回答像不像”，而是工具调用链是否可控、可解释、可失败。

## 阶段性评估

检查重点：

- Agent 是否真的需要调用外部能力。
- tool、resource、function 或 CLI 的输入输出是否清楚。
- 参数 schema、权限边界和失败路径是否明确。
- 当前上下文是否来自工具结果，而不是模型猜测。
- 是否需要 mock、fixture 或 demo 复现。

## 交付评估

检查重点：

- 正常路径是否可用。
- 参数错误是否有结构化处理。
- 工具失败、超时或空结果是否有降级说明。
- 权限不足是否不会泄露敏感信息。
- 回答是否基于工具结果，并能说明来源或证据。
- 是否有最小 demo、测试或手动验证步骤。

## 停止线

出现以下情况应停止并交给人确认：

- 权限边界不清。
- 工具输出和最终回答冲突。
- 失败路径未处理。
- 工具会执行写操作、删除操作、支付、权限变更或生产操作，但没有确认机制。
- 外部资料来源无法确认且会影响决策。

## 输出要求

最终输出应包含：

- 使用了哪些工具能力。
- 输入、输出和关键参数。
- 正常路径和失败路径验证。
- 权限边界和敏感信息处理。
- 未验证项和降级方案。
- 交付状态。
