# 新功能评估标准

## 适用边界

适用于新增用户功能、API、CLI 能力、页面、后台任务、数据处理流程和工具能力。

新功能评估的核心不是“实现了代码”，而是“需求边界内的关键行为有证据证明可用”。

## 阶段性评估

用于设计、接口落地或分步实现过程中。

检查重点：

- 目标用户、输入输出和成功标准是否明确。
- 是否已经区分必须做、可选做和不做的范围。
- 新增接口、配置、数据结构或命令是否和现有模式一致。
- 当前阶段是否有局部验证，例如单测、类型检查、构建或手动验收。
- 是否发现需求边界变化，需要回到计划或 Spec。

## 交付评估

检查重点：

- 核心路径是否有测试或明确手动验收。
- 错误路径、空数据、权限不足、重复提交等关键边界是否处理。
- 新增 API、配置或命令是否有文档或示例。
- lint、typecheck、build 或项目等价检查是否通过。
- diff 是否只包含本次功能相关改动。
- 是否生成或更新 `docs/changes/`。

## 停止线

出现以下情况应停止并交给人确认：

- 需求边界不清，无法判断完成标准。
- 核心行为没有测试、手动验收或其他可复验证据。
- 新功能引入权限、安全、支付、数据迁移或发布风险但没有 Spec。
- 新接口或配置会破坏兼容性，但没有明确授权。

## 输出要求

最终输出应包含：

- 功能目标和完成范围。
- 新增或修改的公开接口、配置或命令。
- 关键路径验证。
- 未覆盖边界和剩余风险。
- 是否需要后续文档、监控或灰度。
- 交付状态。
